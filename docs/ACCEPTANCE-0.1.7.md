# 0.1.7 验收记录

> 结论先说：**自动 lane 全绿；真浏览器台架逐项交互通过；真实应用窗口里只由你本人点过若干项**
> （我连不进渲染进程，见文末「验证缺口」）。这份记录是「试用几天再发 npm」的判断依据。

## 1. 验收入口与环境

| 层 | 命令 / 入口 | 覆盖 |
| --- | --- | --- |
| 单元 + 契约 + 静态 | `npm test` | 112 条 lane：`core`（纯派生）、`contract`（假模块加载器驱动注册面与交互）、`plugin`（打包产物静态断言）、`a11y`、`alignment`（需宿主源码） |
| 源码对齐 | `DSH_SOURCE=~/deepseek-harness npm run verify:align` | 11 条：对着 `dsh-v0.2.1-alpha.5` 源码校验 slot 名、`Menu` 受控契约、`StateDot` 词表、图标导出、`workspaces`/`uiWorkspace` 方法签名 |
| 打包 | `npm run verify` | 重新构建 + `node --check` + 全部 lane + 产物与源码一致 |
| 真浏览器 | 维护者本地台架（静态服务器 + 真浏览器，不随仓库分发） | 真 React + 真 DOM + 真鼠标/键盘，逐项交互 |

台架要点：页面必须是**前台标签**（后台标签会节流 rAF，拖动与粘滞测量都会失真）；换端口可绕开
浏览器对 `harness.js` / `client.js` 的缓存。

台架对宿主的模拟程度决定了它能验到哪一步：`insertSessionBefore` / `insertBefore` / `pin` / `unpin`
/ **`archive` / `unarchive`** 会改台架自己的状态（因此能验「归档后行离场、取消归档后菜单变回」），
搜索走假索引，**重命名走 `sessions.using(id, …, ref => ref.binding.session.rename(title))` 的
真实回调形状**（早期台架只 resolve `{ok:true}`，导致重命名“看起来没生效”——那是台架缺口，不是插件缺陷）。

## 3. 验收跑出来的真 bug（已修 + 回归）

1. **「展开其余 N 个会话」死按钮**：显示行数取 `max(已存页码, 注意力要求)`，而展开从已存页码起跳；
   注意力把区块撑过下一页步长后点击无效。修为从生效页码起跳，新增 lane 用旧产物跑会失败（已验证）。
2. **P1–P4 胶囊不刷新**：`renderRow` 的 `useCallback` 依赖漏了 `priorities`，一直用旧快照；
   宿主里因 store 落盘、重挂载后「看起来正常」。修后在真浏览器里写入即重绘。

## 4. 验证缺口（未验收项，诚实标注）

- **真实应用窗口**：我无法连入渲染进程（HTTP 端口需 token；inspector 端口只在装了
  `@deepseek-ai/dsh-experimental-inspector-profile` 时开放，当前 profile 未启用）。因此
  「实机逐项点击」只有你本人做过的那几项：分区/目录分层、三级缩进、折叠箭头、`⋯` 菜单。
  其余通过项都是 **lane + 台架** 级证据。
- **拖动类动作**会改写你的真实会话顺序，我没有在你的列表上替你点过：实机属于未验收。
- **剪贴板**（复制 Session ID / 工作目录）在台架里不产生宿主调用，已改为在 lane 里断言剪贴板
  写入内容；实机未点。
- **窄栏（rail）折叠态**：harness 未提供该参数，只有 lane 断言调用 `expandSidebar`，未做台架视觉验收。
- **浅色主题**：四档配色按 token 推导在明暗两套主题下都成立（强调色 + 反色文字是主题自带的配对），
  但我只在深色 token 下做了台架实测。
- **官方子槽被遮蔽的副作用**（`ui-schedule` 定时任务标记等）未在实机逐项确认。

### P0 — 拖动（会改写真实顺序）

**安全做法**：先「添加工作区」选一个临时目录（例如 `/tmp/dsm-drag-check`），在新工作区里点行内 `+`
开 2–3 个空白会话，在那里拖——真实工作区的顺序完全不动。拖完可以删掉该工作区（宿主侧删目录即可）。

| # | 怎么点 | 预期 | 自动化覆盖 |

| 7 | 在一个工作区内把会话 A 拖到 B 上方 | 松手后落位；**其间不出现文字选中**；重启后不变 | 台架真鼠标已验 |

## 6. 试用期怎么验

1. 按 §5 的清单从 P0 往下点，先做 1–6（同一类「点了没反应」缺陷），再拖动（7–11）。
2. 观察一天后再看：会话顺序是否持久、优先级胶囊是否跨重启保留、正在运行的会话是否稳定显示旋转点。
3. 若发现问题：`~/.dsh/logs/` 与 DSH 桌面的控制台；
   停用插件（profile 里关掉开关）即可回到官方会话区，插件不写任何 profile 之外的状态。
4. 确认无回归后再执行 `docs/DEPLOY.md` 的「发布到 npm」清单（**本次未执行**）。
