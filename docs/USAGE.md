# 使用说明（0.1.7）

本插件在官方 `sidebar.workspaces` slot 上渲染左侧会话区。所有会话状态都读写 DSH 宿主服务，
插件不保存会话私有数据。

## 会话顺序

三条路径都写入宿主**耐久**顺序（`workspace.sessionIds`），互不冲突：

| 操作 | 行为 |
|---|---|
| 直接拖动会话行 | 指针手势（非 HTML5 拖放）：行上半 = 插到目标之前，下半 = 插到目标之后；拖动中显示 2px 插入线；松手即写宿主，拖动后的那次点击不会顺带打开会话 |
| `Alt + ↑` / `Alt + ↓` | 当前行上移 / 下移一位（键盘等价路径） |
| 行菜单「上移 / 下移」 | 同上，写入同一个宿主调用 |

写入一律走 `workspaces.insertSessionBefore(workspaceId, sessionId, beforeSessionId)`；
省略 anchor 即追加到末尾。**不做乐观重排**：落点无效（同一格）时不发写请求，失败时按宿主返回报错。

限制：

- **未分组会话**（不属于任何工作区账户）不参与排序——宿主 API 需要 `WorkspaceId`。
- **置顶区**不排序：宿主 `pinSession` 只能前插，没有「移动 pin」接口，插件不自造一份顺序。
- 跨工作区拖动会话不在本插件范围内（宿主没有表达"换工作区"的 move API）。
- 置顶会话区不参与拖动：宿主的置顶集合只有 pin/unpin，没有移动 API。
- 行内「⋯」等控件上的按下不会启动拖动：只有落在行本体上的按下才会布防手势。
- 拖动期间的插入标记按帧合并发布，边缘自动滚动也按帧进行（不是每个指针事件都刷一次列表）；
  松手时按手势记录的最后一个标记落位，因此快速甩动也能正确插入。
- 拖动用指针手势而非原生拖放：`draggable` 会被子元素继承、`-webkit-user-drag` 会覆盖
  `draggable="false"`，原生拖动一旦启动就会以 `pointercancel` 打断手势。

## 分区与目录的视觉层级

- **macOS 上的吸顶表头**：侧栏是窗口 vibrancy，因此分区带与目录行在 macOS 上用"标签墨色 6% +
  背景模糊"的玻璃做法（同宿主自己的悬浮控件），不会出现比侧栏更深的色板；Windows / web 仍用
  不透明填充 + 抬升底色。想更强/更弱只需调这个百分比。
- **分区标题带**（置顶会话 / 项目会话）：两者共用同一个控件与样式，文字左边缘对齐
  （32px、14px 半粗、次级色、抬升底色 `--dsw-alias-bg-layer-2` + 细下边线）。
- **工作区目录行**：32px、14px 常规、主文字色 + 文件夹图标，比分区标题缩进一级。
- **优先级标记**（`P1`–`P4`）：同一个强调色的四档权重 —— P1 实心、P2 45%、P3 22%、P4 灰（10%），
  一眼能分等级；不使用状态色（红/琥珀/绿/中性），避免和状态点混淆。
- **会话行**：两种缩进（不再跟随宿主的 `--dsh-workspace-indent`）。
  - 直接挂在分区标题下的行（置顶区、搜索结果）：浅缩进 14px，标题 42px，贴着分区标题的 30px
    —— 顶层列表，不与项目区对齐（同 Codex）。
  - 置顶区**不画图钉**（这里每行都已置顶，图钉只占标题宽度）；置顶会话出现在搜索结果里时仍带图钉。
  - 工作区分组内的行：缩进 32px，标题 60px，与工作区名（62px）对齐。

## 分区折叠与定格

- **置顶会话**、**项目会话** 各自可折叠（点表头）；「项目会话」一次收起/展开下面所有工作区分组。
- 表头**定格**：滚动时分区表头钉在列表顶部，滚进某个工作区分组后由该分组表头接管
  （表头底色用侧栏不透明填充，行从下方穿过，不会透出）。

## 分区结构

一级标题「工作区」下依次是：

1. **置顶会话** —— 独立分区，可单独收起，顺序取宿主 `pinnedSessionIds`，且不在原工作区重复出现；
2. **项目会话** —— 分隔标题 + 一条细线，不做独立折叠，工作区分组紧随其后；
3. **工作区分组** —— 文件夹图标 + 折叠箭头 + 工作区名（悬停显示宿主登记的目录路径），行内可新建会话。

## 视图选项

会话区标题右侧的 `⋮` 菜单：

- **顺序**：手动顺序（宿主耐久顺序）/ 最近活跃（按 `updatedAt` 倒序）。
- **归档**：隐藏归档 / 显示归档 / 只看归档。

工作区分组标题本身也可拖动，落到另一个分组的上/下半即调整工作区在宿主注册表里的顺序
（走 `workspaces.insertBefore`）。

## 状态小圆点

**一行一个点**。主点复用官方 `StateDot` 词表，只回答一件事：这行有没有在动、是不是在等我、有没有
完成没看。

| 状态 | 表现 | 判定来源 |
|---|---|---|
| 等待用户 | 琥珀主点 + 时间列换成「等待批准 / 等待计划确认 / 等待回答」 | `uiSession.sessionStatus.pendingInteraction` |
| 有活在跑 | 转圈主点（本会话 agent / 子会话 / 后台任务，任一在跑都算） | `sessionStatus.running` + 子会话目录 + `jobs.state.rows` |
| 已完成未读 | 绿主点 + 标题加粗 | `sessionStatus.completionUnread` |
| 空闲 | 官方 `idle` 灰色主点（每行恒定一个点，列不会忽有忽无） | 以上都不成立 |

与官方 `sidebar.workspaces` 的读法一致：行内只有**一个** `StateDot`；"未读"不再加文字胶囊，
因为绿点 + 加粗标题已经说完，额外的标记只会和优先级胶囊抢宽度。

优先级写死在一处：`等待 > 执行中 > 已完成未读 > 空闲`（"执行中"内部再按 本会话 agent > 子会话 >
后台任务 归并成一个转圈——一个图形只表示一件事：这行有活）。

**细节在悬停里，不在第二、第三个点上**：主点的 `title` 与读屏文案同源，会拼出完整构成，例如
「正在执行，1 个子会话执行中，1 个本会话的后台任务执行中，2 个子会话的后台任务执行中」。后台任务
按归属分开计数（`jobs.own` / `jobs.subtree`），所以这一个点也能说清"是谁的任务"；但行内不再为每类
活动各画一个标记——四个圆点比一句话更难读。

**不显示失败态**：客户端没有会话级失败位。0.1.x / 0.1.7 早期用"后台任务 roster 里的 failed"
与"`subagentTiming.lastTurnCompleted === false`"近似，实测两者都会误报（roster 保留已结算任务；
被打断或仍在等待输入的子会话同样是 `false`），因此 0.1.7 不再让红点出现在会话行上。
这两个计数仍由 `statusOf(...).facts` 提供，供能精确归因的界面使用。

颜色全部取官方 `--dsw-alias-state-*` token，跟随主题（含第三方主题）。

**能看、能指**：主点只有 10px，所以它的含义同时放在三处——悬停主点会显示上面那句状态说明；
命中区用伪元素扩到整行高度，视觉尺寸和布局都不变；等待类状态的时间列在悬停 / 键盘聚焦时不再让位
给行尾菜单，避免"指针移过去想看，文字却没了"。

**任务流按需开启**：宿主只为**被订阅**的会话维护后台任务 roster。插件订阅「当前画出来的行 ∪ 它们的
子树」，折叠的分组、翻页之后的行不订阅，展开时再补；停用 / 卸载 / 注册生命周期结束时全部释放。
宿主没有 jobs 服务时保持 fail open（列表照常渲染，只是没有任务标记）。

## 会话操作

行尾 `⋯` 菜单：置顶 / 取消置顶、重命名、分叉、归档 / 取消归档、上移 / 下移、复制 Session ID、
复制工作目录（仅当宿主摘要带 `cwd`）。

- 置顶 / 取消置顶（宿主里的 pin 集合，界面上一律叫"置顶"）、归档 / 取消归档、分叉、重命名全部调用宿主服务，不使用 localStorage。
- 归档运行中的会话会被宿主拒绝，插件把拒绝原因显示为提示条，不自动停止会话。
- 置顶顺序按宿主 `pinnedSessionIds`；置顶行从工作区分组中移出，取消置顶后回到原分组。
- 工作区标题悬停显示宿主登记的目录路径（`workspaces.items[*].path`）。
- 每个工作区分组标题右侧有「+」，调用宿主 `startSession(workspaceId)` 新建会话。

## 关闭或卸载插件后

- slot 注册随插件生命周期消失，官方会话区立即恢复渲染，无需迁移或清理脚本。
- 宿主会话、工作区归属、置顶、归档、顺序数据全部保持原样。
- 启用期间官方 5 个子槽（会话菜单项、行内按钮、定时任务标记与悬停节、目录流）的贡献不会出现；
  详见 README 的「与官方会话区的关系」。

## 数据归属

| 状态 | 归属 | 插件行为 |
|---|---|---|
| 会话顺序 | 宿主 `workspace.sessionIds` | 只调 `insertSessionBefore` / `insertBefore` |
| 置顶 / 归档 | 宿主 `pinnedSessionIds` / `archivedSessionIds` | 只调宿主服务 |
| 会话标题 | 宿主持久标题 | 重命名走 `sessions.using(...).binding.session.rename` |
| 当前选择 | 宿主 `retainedBy.mainView` | 只读 |
| 折叠状态、视图选项 | 插件组件内状态 | 不落盘，刷新回默认 |

## 添加工作区

会话区标题右侧的 `+`（空列表时也会显示一个「添加工作区」按钮）调用宿主
`uiWorkspace.pickDirectory()`：由宿主决定用原生目录选择器还是应用内目录浏览器；返回路径后
再调 `workspaces.create({ path })` 登记成真正的工作区。取消（返回 `null`）不产生任何写入。

## 优先级视图（分类查看 + 批量修改）

头部那个 **P 徽标**（打开时变成实心强调色）进入**优先级视图**：

- 列表按等级分区：`P1 · 最高` … `P4 · 参考`，**空等级不占位**；最后是「未标记」分区，
  默认折叠（要给没标记的会话打标时展开它）。
- 打开后列表上方是批量条：`已选 N 个` + `P1` `P2` `P3` `P4` + `清除标记` + `选中已标记` /
  `清空选择` / `完成`。勾选任意行，再按等级即可整批改；`清除标记` 一次清空所选行的优先级。
- **勾选框固定在最前面**（在状态点之前），所以选择列永远在同一个位置；**点标题仍然是打开会话**，
  勾选不会误开。
- 批量写入合成**一次**存储写入，选中很多行也只重绘一次；`完成`（或再点一次那个图标）退出视图，
  恢复置顶会话 / 项目会话结构，并清空选择。

典型用法：一批需求评审完 → 进优先级视图 → `选中已标记` → `清除标记`。

## 置顶区排序与优先级标记

- **拖动置顶区会话**即可调整置顶顺序：宿主 pin 集合是“前插、无 move API”，插件重写改动的最小
  后缀（unpin → 按目标顺序逆序 pin），拖动时置顶区立刻显示目标顺序，写入稳定后交回宿主顺序。
- **优先级标记**：行的 `⋯` 菜单 →「优先级标记」→ P1 最高 / P2 较高 / P3 普通 / P4 参考 / 清除。
  标记是行尾的 `P1`…`P4` 数字胶囊，四档同属一个强调色、按等级分权重：
  **P1** 实心 + 反色文字、**P2** 45% 底色、**P3** 22% 底色、**P4** 灰字 + 10% 灰底。
  **不占用状态色**（红 = 失败、琥珀 = 需要你处理、绿 = 完成未读、中性 = 空闲）：
  色相只留给状态点，优先级用同一个色的深浅区分，两者永远读得开。
- 标记存在官方 `dsh-client-store` 的持久化槽（键 `dsh-session-manager.priority`），
  重启、重装插件都保留；卸载插件后该键会留在浏览器存储里，可手动清理。
  0.1.7 早期按颜色存过的值（`red|amber|green|blue`）会自动映射到 P1–P4。

## 分区内顺序

工作区分组内提供两种顺序：**手动顺序**、**最近活跃**。
宿主 `SessionSummary` 只有 `updatedAt`，没有创建时间字段，所以没有独立的“创建时间”模式——
不过「手动顺序」的初始值就是宿主的登记顺序（≈创建顺序），只有你拖动过才会偏离。

## 会话搜索

标题栏 `⌕` 打开搜索框：

- 本地匹配会话标题与工作区名，再合并宿主消息内容索引（`sessions.search`）的命中；
- 结果按最近活跃排序，命中片段显示在行内；点行打开会话；
- 输入有 250ms 防抖，前一次请求在下次触发前被 abort；查询按宿主契约清洗（去 NUL、上限 500
  UTF-16 码元且不截断代理对）；空白查询不会发请求；
- 命中数达到宿主上限时提示「结果较多，请细化查询」；
- `Esc` 或 `×` 关闭搜索并回到列表。

## 会话分页

每个区块（置顶区除外）默认显示 5 行，其余折叠为「展开其余 N 个会话 / 收起」：

- 有运行中 / 等待交互 / 已完成未读 / 失败标记的会话会自动抬升分页（前 50 行内有效），
  绝不会被折叠隐藏；
- 点击展开按 5 行递增；剩余不足一页时一次展开全部。
